## Important findings

1. **The permitted Escape override contradicts the frozen Modal requirement.** `specs/components/modal.md:11` exposes `closeOnEscape: boolean` and only rejects `true` when the icon close button is absent. Consequently `{showCloseButton:true, closeOnEscape:false}` is a valid documented configuration. `specs/components/modal.md:21` then expressly suppresses Escape for it. This contradicts the same spec's Official requirements at line 7 and the frozen guide: `upstream/krds/raw/components/component_04_05.html:1187`, repeated at line 1231, says “모달에 닫기 버튼이 제공되는 경우 닫기 동작을 실행한다.” For an actually open, topmost modal with a close button, an unhandled non-composing Escape must request dismissal. Remove this independent opt-out for that configuration or reject it as an invalid configuration. The topmost/inner-widget/IME safeguards and controlled-parent rejection behavior can remain; none requires a permanent opt-out.

2. **The focus override options permit destinations outside the stated official contract.** `specs/components/modal.md:17` allows `initialFocusId` to identify any enabled focusable descendant, including a later action or the final close button. `specs/components/modal.md:23` always prefers `returnFocusId`, even when the opening control still exists and is usable. The frozen requirement at `upstream/krds/raw/components/component_04_05.html:1134` specifies initial focus on “모달 자체 또는 모달 내에서 상호작용이 가능한 첫 번째 요소” and closing/cancel focus on “모달 열기 버튼”. The spec itself repeats those destinations at line 7. Constrain the initial override to the dialog/first interactive element and use an alternate return target only when there is no usable opener (including initial-open dialogs). Preserve the explicit removed-opener fallback. Otherwise an adapter must choose between the sanctioned API options and the authoritative KRDS rule.
