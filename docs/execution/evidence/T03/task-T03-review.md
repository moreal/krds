# T03 independent review

Spec: ❌ — collection, source boundaries and current package notices satisfy the reviewed requirements, but the verification gates have two Important gaps.

Quality: **Needs fixes**. No Critical findings. No selected asset was found to have unresolved rights or an invented copyright holder.

## Findings

1. **Important — release verification can approve an explicitly incomplete independent-code grant.** `tools/verify-licenses.mjs:48`–`55` considers only three identity checks. It never reconciles `license-policy.json`'s `independentCode.holderStatus: "unconfirmed"` / `releaseAllowed: false` or verifies that the independently authored code has a completed actual license grant. Consequently, confirming the checked scope, holder and repository fields makes `--release` pass while `LICENSES/MIT-intended.txt` and the generated package licenses still explicitly say the grant is incomplete. I reproduced this in a temporary fixture using the selected Node through `tools/yarn.mjs`; the fixture retained those independent-code policy blocks and incomplete grant. This is a local candidate-readiness defect, separate from permission to publish: no new external publishing approval is required to fix it. Keep release verification blocked until the independent-code license policy and completed notices agree with the confirmed identity, and add a regression case where identity is confirmed but the grant remains incomplete. The present frozen identity and unconditional prepublish guard still prevent this snapshot from being published through the supplied scripts.

2. **Important — valid package `files` globs bypass shipped-asset provenance checks.** `tools/generate-notices.mjs:116` silently skips every whitelist entry containing glob characters. A package with `files: ["payload/*.svg", ...legalFiles]`, no configured static root for that directory, and an untracked `payload/mystery.svg` therefore passes generation and verification with zero source records. The same selected Yarn 4.14.1 packed a minimal temporary package with that whitelist; inspecting its tarball confirmed `package/payload/mystery.svg` was included. Thus a normal package-metadata change can cause the gate to claim success for shipped bytes with no verified rights or notices. Resolve the packing selection, or fail closed on unsupported patterns with an actionable error; a focused rejection is sufficient for this task. Add a regression test. Current public manifests use literal roots and the reported 13 tarballs were inspected, so this does not establish a current untracked payload.
