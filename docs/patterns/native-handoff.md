# Native composition handoff

The common interface is ready for native integration. The controller assigns each adapter/fixture/Storybook owner separately. This handoff does not authorize changes to another owner's directories, shared styles, catalog coverage, dependencies, lockfile, root runner or package exports. Seven stable renderers are required: Solid 1, React, Svelte, Vue, Lit, Qwik and Angular. Solid 2 remains an isolated preview and is not substituted for Solid 1 or counted toward those seven.

## Import and host boundary

Import `createPatternState`, `transition`, `createLocalDriver`, `getPresentation`, `patternScenarios` and content from `@unofficial-krds/test-contracts/patterns`. The controller/common package owner adds that package export; the common implementation lives only in `packages/test-contracts/src/patterns/**`. Do not add app-relative imports into root `examples/data`, copy handwritten declarations or create a new workspace. Runtime declarations are emitted by the existing selected TypeScript compiler. The module remains private test/example infrastructure; public adapter packages must not depend on it.

For a pure native presentation component, receive a discriminated `PatternState` plus native action callbacks/slots. The common model returns only JSON state and effects; it never owns DOM, refs, events, routing, focus, portals, forms or a renderer. `fieldIds` are semantic target IDs. Resolve effects against real native controls after render. A recorded `focus` effect alone never proves actual browser focus.

For an integration fixture:

1. Match the exact `/examples/<patternId>?case=<caseId>` route to a `patternScenarios` entry. Construct a route-scoped `createLocalDriver(patternId, {caseId, seed, initialState?})` and apply its `initialActions` before first render. The `filter-resets-page` case uses initial page 3; other scenarios use their explicit initial actions. Optional `initialState` adopts a cloned, typed, ready/nonpending snapshot; it does not dispatch, settle, emit requests or replay scenario actions. The host applies those actions exactly once, either before adoption or after constructing the driver, never both.
2. Initialize native state from `getState()`, then subscribe. Each user semantic callback dispatches one `PatternAction`. Perform returned focus effects after the native DOM commit. Record each actual request effect once as existing fixture event `pattern:request`, with `{operation, requestId, payload}`; do not record effects for no-op actions.
3. Keep request settlement in the fixture host. A request stays visibly loading until an explicit `settle()`; no timers, fetch, storage or automatic retries exist in the driver. Seed `success` succeeds, `error-once` fails its first completion then succeeds, `error` always fails, `loading` holds until `settle({ok:true/false})`. The seed configures completion, not automatic initial submission.
4. Reuse the existing `window.__KRDS_FIXTURE__` protocol-1 bridge. Test code calls `setState({__patternCommand:{sequence:1,command:'settle'}})` with a monotonically increasing sequence. The native fixture host consumes each sequence once and calls local `settle({ok})`; replaying a bridge snapshot must not settle twice. This is additive host interpretation of the existing JSON patch protocol, not a change to pilot driver methods. Tests open the example URL directly; the existing pilot driver's `/fixtures/...` route builder stays unchanged.
5. The bridge's initial/getState data may remain fixture control data. Inspect actual DOM for displayed state and real focus, and use `pattern:request` events for actual request counts. Never fake DOM success through bridge patching. A UI click/keyboard event must initiate the corresponding request before a test releases it.
6. On route teardown unsubscribe, dispose the local driver and existing bridge, and remove native listeners/portals. Pending work is local and cannot complete after disposal. Reset/cancel also invalidate pending IDs; ignored late replies cannot modify the view.

The command envelope type is `PatternFixtureCommand`. A host may render a visibly labeled local test-control area outside the service composition for interactive development, but it must call the same local driver and must not become a service flow or appear in presentation stories. The sample model is deterministic and does not need an actual API or auth service, including same-origin endpoints.

For initial URLs and popstate, the host may normalize search criteria over `createPatternState('search-results', caseId)`, then overlay `query`, `appliedQuery`, `category` and the pure `searchResources({query, category, page})` result. Preserve the case's page default when the URL omits page; the pure matcher clamps an explicitly supplied page. Pass that ready snapshot as `initialState` rather than synthesizing a search request/completion. Initialization requires a matching pattern, a nonnegative safe-integer request counter, an allowed settled phase and null pending/failed payloads; search initialization additionally requires a successful, coherent three-per-page result slice for its applied criteria. It retains supplied counter/history data but creates no new history. The seed still controls only future completion, and normal `reset` restores the original model defaults rather than redefining them from the adopted URL. This typed initialization guard is not a general parser for untrusted state; URL parsing/normalization belongs to the native host.

## Exact routes and scenarios

| Pattern / route prefix | Case IDs |
| --- | --- |
| `/examples/form-errors` | `error-summary-focus`, `retry-success`, `reset-cancels-pending` |
| `/examples/search-results` | `filter-resets-page`, `empty-results`, `retry-success`, `query-during-loading` |
| `/examples/consent-confirmation` | `required-refusal`, `optional-refusal-success`, `modal-focus-return`, `retry-in-dialog` |
| `/examples/service-layout` | `skip-main`, `navigate-current`, `narrow-navigation`, `footer-policy` |

`patternScenarios` supplies every literal initial action and expected native outcome. Case IDs are scoped by pattern. For search links, preserve `case/query/category/page`; for layout links, preserve `case` and set `section`. Owners implement real same-origin URLs, initial URL normalization and history/back-forward behavior. The pure module deliberately reads no browser location.

Required focus outcomes: invalid form submit → first invalid real field; error-summary link → named real field; instant filter → retain category-select focus and reset page 1; dialog open → container/first allowed element according to Modal contract; actual close → usable opener plus saved page position; layout destination change → new main heading; canceled mobile menu → opener. Keep actual Modal cleanup and controlled rejection semantics. No return-focus request may override a still usable saved opener.

A current layout destination is also an activation when a mobile layer is open or its containing branch is collapsed: close the layer, expose the branch and focus the existing main heading without emitting a route change. Do not discard that action because the route ID is unchanged. When the current branch is already visible and no layer is open, preserve the genuine no-op and emit no focus effect.

## Natural composition in each renderer

| Owner | Native composition and lifecycle | Additional real evidence |
| --- | --- | --- |
| Solid 1 | JSX components/children, native form events, signals/store for model snapshots, refs and `onCleanup`; callbacks consume semantic details once. Use only the stable Solid adapter/runtime. | Run native flow tests, actual form reset/focus and portal teardown. Do not import Solid 2 compiler/runtime. |
| React | React components/children, state/reducer or external-store subscription, native form events, refs and effects with cleanup. Construct one driver per route lifetime and dispose each mounted instance, including development remounts. | Real input focus and FormData/reset; no duplicate requests from effect remounts. |
| Vue | SFC templates/slots with refs and computed data; either a controlled value plus `valueChange` callback or the adapter's supported model binding. Do not dispatch twice by handling both model update and semantic value-change for the same action. Use `nextTick` for post-render focus and unmount cleanup. | Native field/error associations and exact one request per accepted semantic action. |
| Svelte | Native `.svelte` components/snippets, `$state`/derived snapshots and semantic `onValueChange` callbacks; `tick` for focus, effect/onDestroy cleanup. Compile through the actual Svelte package export. | Actual native form/reset and independent package-consumer compile. |
| Lit | Register and compose the actual custom elements in native Lit templates, property bindings for state/arrays and actual composed semantic custom events such as `value-change`. Await `updateComplete` before focus. Use lifecycle cleanup. | Shadow DOM accessible naming, actual internal control focus, FACE FormData/reset and real submitter behavior. A host `id` is not proof of an inner input target. No invented siheom adapter. |
| Qwik | Native `component$` composition, serializable state/signals and `$` event handlers using the Qwik adapter's QRL callbacks such as `onValueChange$`. A mutable driver closure/subscriber set is not serializable state: keep the pure state reducer as the persisted truth and adapt fixture-only local completion without serializing that closure. | Production SSR serialization/resume and the first lazy input/click/key must run this composition. Do not eagerly hydrate every control or replace Qwik with another renderer. Keep selected Vite 7. |
| Angular | Standalone native components/templates, inputs/outputs and signals; integrate actual forms/CVA controls through reactive forms with one source of truth. Use normal Angular lifecycle/render scheduling for refs/focus and destroy cleanup. | Real CVA form reset/value behavior, AOT/partial APF external-consumer compile and SSR through official CLI/ng-packagr. A generic Vite render is insufficient. |

These are renderer integration expectations, not a claim that every full-catalog export is already accepted. If a component required by a flow is still being implemented, the native owner reports that dependency and proceeds when its own adapter is ready. Plain semantic host sections such as the summary/main heading are allowed; foreign-renderer wrappers and label-only replacement components are not.

## Presentation stories and completion evidence

Stories import a cloned `getPresentation(patternId, variant)` snapshot and supply it to the same native presentation component through local args/inputs/slots. They do not construct the local driver, invoke settle, fetch an API, load external fonts/images or put integration scenarios in `play`. Sixteen snapshots are exported; their presence is not executed Storybook support. Solid 2 has no claimed upstream Storybook/siheom support.

Native integration tests are separate behavior files. In supported frameworks use the selected upstream siheom path where applicable and real browser contract tests. Lit uses its actual native browser test route. Each stable owner must exercise all fifteen scenarios, failure/retry/loading, native keyboard/focus/scroll, narrow/200%/forced-colors presentation, zero external requests and cleanup. Also run its own build/typecheck/story checks and required SSR/resume/CVA/Shadow DOM gates. Inspect raw accessibility findings and actual screenshots; a runner exit code or descriptor count is not coverage acceptance. The shared logic test suite proves only host calculations and state transitions.

No framework completion, catalog coverage promotion, source/license clearance or T11 completion follows automatically from this handoff. Controller-owned independent review and real seven-framework compositions remain outstanding.
