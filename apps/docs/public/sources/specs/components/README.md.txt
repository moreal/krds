# 네이티브 계약 규약 {#native-contract-conventions}

이 계약은 모든 네이티브 어댑터를 구속합니다. 각 컴포넌트 명세와 함께 읽습니다. 공유 타입은 `@unofficial-krds/contracts`가 export합니다. 어댑터는 자체 네이티브 children, ref, 리스너, 콜백 전달을 더합니다. 렌더러 타입은 공유 패키지에 들어가지 않습니다. 이 문서는 동작을 규정할 뿐이며, 어댑터가 구현했다는 근거가 아닙니다.

## 출처와 정책 경계 {#source-and-policy-boundary}

아래 공식 요구사항은 각 명세에 링크된 고정 KRDS 상세 페이지의 의역입니다. 원천 식별 정보, 조회 시각, 바이트, SHA-256은 `upstream/krds/manifest.json`에 기록되어 있고 `catalog/components.json`에 반복됩니다. 기준선: `krds-web-2026-10-30-kit-1.1.0-d6bb184c823e`, 조회: 2026-10-29 UTC(한국 2026-10-30). 고정된 라이브 웹사이트는 키트 태그 1.1.0과 별개입니다. 프로젝트 기본값은 KRDS가 규정하지 않은 세부를 정하며, KRDS나 Ark/Zag 기본값에 대한 주장이 아닙니다. 원본 KRDS JavaScript는 어댑터 DOM을 제어하지 않습니다.

## 상태와 알림 {#state-and-notifications}

정의된 `value` 또는 `open`은 빈 문자열, null, false, 빈 범위를 포함해 제어 모드를 택합니다. 없음(`undefined`)은 비제어 모드를 택합니다. 제어 prop과 대응하는 `default*`를 함께 주면 구성 오류(`TypeError`)입니다. 마운트 후 모드를 바꾸는 것도 구성 오류입니다. `default*`는 한 번만 읽으며 이후 변경은 상태나 리셋 기준선을 바꾸지 않습니다. 제어 prop이 우선합니다. 동작은 변경을 요청할 뿐이며 표시되는 커밋 상태는 부모가 prop을 바꿀 때만 바뀝니다. prop 갱신, 마운트, 하이드레이션, 기본값 초기화, 초점 이동, 폼 리셋은 사용자 변경 알림을 내지 않습니다.

비제어 상태는 수용된 사용자 동작마다 동기적으로 한 번 바뀌고 그 갱신 후 한 번 알립니다. 제어 동작은 부모가 거부해도 요청을 한 번 냅니다. 현재 커밋 값을 요청하는 동작, 비활성 동작, 유효하지 않은 동작은 알림을 내지 않습니다. keydown/click, input/change 리스너 쌍에서 두 번 내지 않습니다. 시맨틱 콜백은 `onValueChange(ValueChangeDetails<T>)`와 `onOpenChange(OpenChangeDetails)`입니다. 네이티브 프레임워크의 이벤트 이름과 바인딩은 어댑터 API입니다. 이벤트는 프레임워크 이벤트 객체가 아닌 일반 값을 전달합니다. 취소된 네이티브 폼 리셋은 아무것도 하지 않습니다. 취소되지 않은 리셋은 비제어 초기 상태를 복원하고 초안·오류를 변경 콜백 없이 지우며, 제어 상태는 현재 prop을 유지합니다. 폼 상태가 없는 컴포넌트는 폼 리셋의 영향을 받지 않습니다.

각 명세는 시맨틱 옵션을 나열합니다. 어댑터는 네이티브 속성, 네이티브 콘텐츠, 접근 가능한 이름 속성을 받을 수 있지만 다른 동작을 조용히 추가하면 안 됩니다. 잘못된 열거값, 중복된 항목 값/ID, 유효하지 않은 초기·제어 값, 누락된 구조 관계는 구성 오류입니다(`TypeError`, 유효하지 않은 날짜·범위는 `RangeError`). 개발과 테스트에서 드러내며 다른 항목을 조용히 선택하지 않습니다. 동적 옵션 제거로 선택값이 무효가 되면 부모가 옵션과 값을 함께 갱신해야 합니다. 비활성 컨트롤은 포인터·키보드 활성화를 막으며 외부 prop 변경은 여전히 렌더링됩니다. 사용자 검증 오류는 구성 예외가 아니라 보이는 텍스트, `aria-invalid`, `aria-describedby`로 표시합니다.

## 공개 구조와 스타일 {#public-structure-and-styling}

라이브러리 소유 속성은 렌더러마다 동일합니다. `data-krds-component`는 시맨틱 kebab-case ID, `data-krds-part`는 문서화된 파트 토큰 하나, `data-krds-state`는 아래에 나열된 해당 상태를 공백으로 구분한 집합입니다. 빈 상태는 빈 문자열입니다. 전체 문자열 일치 대신 CSS `[data-krds-state~="disabled"]`를 씁니다. 루트와 포털 콘텐츠를 포함한 모든 소유 파트에 컴포넌트 식별을 둡니다. 소비자는 이 속성을 스타일링할 수 있지만 덮어쓰면 안 됩니다. 프레임워크/Ark의 `data-scope`, `data-part`는 구현 세부입니다. 보조 기술에서는 네이티브/ARIA 상태가 우선합니다. 임의의 래퍼 순서를 공개 API로 노출하지 않고 각 명세의 시맨틱 순서를 보존합니다.

모든 컴포넌트는 보이는 키보드 초점, 강제 색상 모드, 200% 글자 확대, 좁은 뷰포트, 동작 줄이기를 지원합니다. 선택, 오류, 비활성 상태에는 색 이외의 단서가 필요합니다. 장식 아이콘은 보조 기술에서 숨깁니다. 명세가 번역된 UI 크롬을 정의하지 않는 한 의미 있는 접근 가능한 이름은 사용자 콘텐츠가 제공합니다. 스타일은 공유 KRDS 토큰 매핑을 써야 합니다. 스타일 완료와 토큰 사용만으로는 접근성 검증이 아닙니다. 전역 리셋, 전체 컴포넌트 CSS, 글꼴은 계속 옵트인입니다. 원격 자산, API, 텔레메트리, 네트워크 상태는 필요 없습니다.

## 커버리지와 인수 {#coverage-and-acceptance}

카탈로그에는 고정된 55개 항목이 있으며 SplashScreen만 공식적으로 웹 범위 밖이어서 웹에 적용되는 항목은 54개입니다. 안정 네이티브 프레임워크 7개와 Solid 2 미리보기는 각각 별도의 계획 항목을 가집니다. 명세, 통과한 빌드, 프로브, 이 계약 스위트는 어댑터 커버리지를 implemented/verified로 바꾸지 않습니다. T10의 48개 계약은 범위 승인된 명세이며 네이티브 커버리지는 계속 보류입니다. 지원하는 케이스 축이 곧 공식 명명 변형은 아닙니다. 수용된 원천/프로젝트 완료 종류 보정은 고정된 원천 종류를 별도로 유지합니다. 조합·통합·자산은 실제 네이티브 및 호스트 결과 전체를 요구합니다. 단계별 전체 스토리와 결과는 활성 파일럿 시나리오 10개 및 활성 파일럿 스토리 6개와 별개입니다. T10이 종합 릴리스 근거 관문을 소유하며 `verify:catalog`는 무결성과 근거 경로만 확인합니다.

## 전체 카탈로그 인터페이스와 출처 권리 {#full-catalog-interfaces-and-source-rights}

[full-catalog.ts](../../packages/contracts/src/full-catalog.ts)는 구체적인 시맨틱 인터페이스, `fullCatalogDefinitions`의 파트·상태 토큰, `fullCatalogPresentation`의 직교 데이터 속성을 고정합니다. 네이티브 어댑터가 네이티브 콘텐츠와 ref를 소유하며, 일반 텍스트 항목 콘텐츠는 항목 ID를 키로 하는 어댑터 소유 네이티브 슬롯으로 확장할 수 있습니다. 공유 범용 렌더러는 제공하지 않습니다. `catalog/full-catalog-contracts.json`은 48개 원천 식별 정보, 줄 범위, 의무, 근거 한계를 모두 색인합니다. `catalog/full-catalog-stories.json`은 단계별 로컬 상태와 기대값을 담으며 파일럿 러너에서 누락된 케이스를 활성화하지 않습니다.

공식 인용·파생 KRDS 텍스트, 글꼴, 자산은 원래의 권리와 고지를 유지합니다. 독립 프로젝트 MIT 코드는 이를 재라이선스하지 않습니다. 가이드 픽셀, 별도로 링크된 코드, 프로덕션 자산 승인은 검토되지 않은 채로 남아 있으며 공식 텍스트 조건은 계속 구속력을 가집니다. SplashScreen만 플랫폼 범위 때문에 제외됩니다.

## 네이티브 조합 식별 추가 {#native-composition-identity-additions}

RadioGroupOption만 명시적 네이티브 input id를 제공할 수 있으며 NativeSelect의 SelectOption은 바뀌지 않습니다. Header와 그 단일 실제 MainMenu는 선택적인 현재/모바일 disclosure, 실제 기본 트리거의 식별·이름, 랜드마크 이름 입력을 공유합니다. 기본값과 기존 이벤트 의미는 유지되며, 이 일반 시맨틱 입력은 렌더러나 머신 객체를 전달하지 않습니다. T11의 명시적 주요 메뉴 / 예제 메뉴 이름은 호스트 조합 요구사항이며, 지어낸 KRDS 공식 기본값이 아닙니다.

## 선택적 FAB 레이블 표시 {#optional-fab-label-presentation}

FAB의 `showLabel?: boolean`은 기본 `true`이며 보이는 주 레이블 표시만 제어합니다. `false`는 아이콘만 표시하도록 요청하며, 필수 `label`은 계속 실제 네이티브 버튼의 이름이 됩니다. 확장 상태의 소유는 액션이 유지하고, 표시 갱신은 액션/확장 콜백을 호출하지 않습니다. [FAB 계약](./fab.md)을 참고합니다. 새 동작 변형을 도입하거나 접근 가능한 이름 요구를 완화하지 않습니다.
