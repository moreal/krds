# Svelte compatibility

The native 54-component source catalog targets the selected Svelte 5.57.3 runtime/compiler, `@sveltejs/package` 3.0.1, `@sveltejs/vite-plugin-svelte` 7.3.1 and Vite 8.3.5. No other Svelte major-generation support is claimed.

The package exports official `svelte-package` output: `.svelte` source plus JavaScript helpers and declarations. `svelte2tsx` 0.7.62 checks a shim filename suffix containing `svelte2tsx/`, while this Yarn pnpm linker resolves it under `.store/.../package/`; its emitter consequently produces empty legacy props. Explicit source declarations using Svelte `Component<Props>` preserve the selected native API through the supported package build. No dependency, lockfile or global tool alteration is used to hide this mismatch.

`apps/fixture-svelte` is a separate consuming workspace, imports `@unofficial-krds/svelte` through public exports and has no package-source alias. Its `DocsConsumer.svelte` compiles all six components, native snippets, provider context and `bind:element`. Its production SSR entry renders without a browser document or import-time DOM access.

Native browser evidence covers controlled rejection and external updates, no prop notification replay, reset and canonical form data, raw IME drafts, date-only validation, sequential tabs/date buttons, Calendar tentative confirmation, modal focus restoration and cleanup. Modal body/footer snippets provide a native `close()` request, including the required explicit-action case when the icon close is hidden. Modal provides a native trigger snippet that records the opening event target rather than assuming pointer activation focuses buttons. Modal and DateInput use native HTML dialog top-layer rendering, background isolation and retained inheritance; no framework wrapper is involved.

The T07 report records exact commands, raw axe/request reports, inspected visual artifacts, source inventory and limitations. Full catalog implementation, actual screen-reader/manual assistive-technology validation, independent registry installation, ownership verification, package release checks, publishing/pushing/tagging remain separate gates. Firefox launch inherits the documented local profile-creation blocker; it must not be reported as passed.
