# Outside tarball consumers

`node tools/yarn.mjs pack:all --build` is the controller-owned serialized public build and pack operation. It builds only the thirteen public workspaces, in internal dependency order, records input/output fingerprints, verifies notices, processes Yarn pack NDJSON, creates actual tarballs and validates all packed file/content hashes, original internal semver ranges, exports, public declarations, CSS, assets and notices. Run it only after implementation owners freeze their public inputs. Subsequent `pack:all` reuses matching attestation and rejects source/dist drift.

`node tools/yarn.mjs inspect:tarballs` rechecks the final manifest against its exact build attestation and current public source/build state. `node tools/yarn.mjs test:consumers` creates fifteen fresh apps below `/private/tmp`: seven stable minimum/current pairs and one exact Solid 2 rc.19 preview. Each app has its own Yarn manifest, pruned lock and pnpm-linked installation. The framework runtime/compiler pins remain exact, with no runtime overrides. Only internal public candidates use app-local resolutions. Original packed internal ranges are checked before overrides and every installed internal file is matched to the candidate hash.

Install resolution starts from the selected repository's **non-workspace npm lock entries only** so the offline cached exact toolchain can be reproduced. Yarn then solves and prunes a separate consumer lock; repository workspace locators cannot survive. Consumer caches are outside the repository and contain cached package archive bytes, not repository node_modules or source aliases. Network is disabled during installation. Runtime/compiler real paths must stay inside the consumer's own node_modules. All selected runtimes, compilers, build tools and Playwright are direct consumer dependencies. No root installation is changed.

Consumers run their actual type tools, native production compiler, server render, and static browser click/keyboard checks. Qwik checks optimizer output, serialized SSR and first resumed interaction; Angular uses official application AOT linking, partial APF secondary imports, static prerender/hydration and a Reactive Forms CVA interaction. Bundle module package identities, public declarations, fonts, aggregate CSS and retained legal notices are inspected. `KRDS_BROWSER=chromium|firefox|webkit` and `KRDS_TIMEZONE=<IANA>` configure the standalone generated `browser.mjs`; Chromium/UTC is the default consumer pipeline. Native catalog behavior and multi-engine SSR coverage remain separately owned checks.

`artifacts/consumer-results.json` is the all-framework report. Filtered `--framework=<id>` diagnostics have separate report names and do not satisfy the aggregate fifteen-row gate. Records include candidate manifest hash, independent lock hash, actual resolved runtime/compiler locations, logs and a harness source hash. Final commands reject missing/stale evidence and all debug inventories.

During live implementation, `pack-all.mjs --debug-existing` inventories already retained tarballs as `artifacts/debug-inventory.json`. `test-consumers.mjs --debug-snapshot` permits genuine compiler/runtime diagnostics against those exact bytes while explicitly recording `debug-only-source-not-accepted`. This does **not** accept stale source, create the final manifest, satisfy final verification, authorize publication, or substitute for the final serialized build/pack/consumer run.

## Scoped v2 evidence

`pack:all --scope=stable --build` requires only the twelve stable/shared packages; `--scope=preview --build` requires only five shared packages plus Solid 2. The default all build persists `manifest-stable.json` before attempting preview-only work, then writes `manifest-preview.json` and finally the complete `manifest.json`. Each manifest has `scopes[scope]` containing its complete `sourceSnapshot`, source/input fingerprints, canonical candidate `artifactSetSha256`, and an exact reference to `build-evidence-<scope>.json`. Build attestations contain actual captured commands and subprocess stdout/stderr/result/log hashes. Added source paths and relevant shared build tools/vendor Yarn bytes participate in the current inventory. Preview-only native files and framework metadata are excluded from the stable projection. Shared lock/tool/rights changes remain common inputs.

`test:consumers --scope=stable` produces fourteen stable rows and `consumer-results-stable.json`; preview produces one exact RC19 row and `consumer-results-preview.json`. An all run refreshes both scoped reports, including failed results, before its all report. Rows and reports bind scope candidate hashes, so a global manifest change or unrelated preview blocker cannot invalidate valid stable evidence. Per-framework diagnostics remain incomplete evidence, and debug reports remain rejected.

The canonical release API is `inspectConsumers(report, {scope, manifest, baseRoot})` from `tests/consumers/evidence.mjs`. It validates current complete source and producer/harness inventories, exact commands and raw subprocess outcomes, immutable stdout/stderr/combined logs, independent lock/config snapshots, actual runtime/compiler manifest/entry/bin bytes, candidate tar copies and every installed candidate file. Native source/config/driver bytes must match the accepted producer templates. SSR output and browser first-interaction observations are parsed from actual captured outputs. Missing, stale, legacy, debug or contradictory evidence throws `EVIDENCE_BLOCKED`; a current hash-bound subprocess nonzero/signal throws `EVIDENCE_FAILED`. Returned `paths` enumerate durable receipts and underlying evidence. Existing v1 debug evidence is historical; it is not migrated into v2 acceptance.

Focused tests are `pipeline.test.mjs` and `interface.test.mjs`. `interface-real.test.mjs` is a session diagnostic requiring the retained actual React consumer; it probes real installed identities and immutable evidence rejection without rebuilding any native package/app or rerunning browser matrices. Its temporary narrowing of unused consumer-local overrides is restored afterward and creates no accepted milestone report.

## Pipeline review fix round 1

Scoped freshness includes the actual root package/Yarn/TypeScript configs, recursively extended compiler configs, real build-script/config imports (parsed with the already selected TypeScript 6 compiler), the two original token JSON inputs, selected provenance source bytes and the transitive rights/terms closure. Generated token mapping and owned dist outputs are excluded only from the pre-build input fingerprint and remain in the complete output fingerprint.

Every accepted scope now requires a `packageCompliance` proof generated by `verifyPackageCompliance` from `compliance.mjs`. This package-only semantic check uses the authoritative schema and generated-notice logic, verifies the complete independent MIT grant, original-first/unmodified source hashes, required original/related terms and copyright, exact generated copies/no extra license files, literal shipping roots and tracked assets. It never loads unrelated app distribution state or preview package trees for stable acceptance. The inspector replays this check before accepting a scope.

Consumer `receipt.outputClosure` includes a strict complete client/server/legal/SSR output inventory, canonical SSR entry/driver, replayable bundle audit and complete legal-material plan. Both Angular client/server compiler stats and other framework bundle records are checked for actual emitted foreign/test runtimes, external imports, aggregate CSS and fonts. Application `_legal/` preserves the full candidate grants/attribution/original terms and original bundled runtime/helper license files; its index and links are canonical and byte checked. A copyright word alone cannot pass. Output changes, deletions and additions—including under otherwise ignored directory names—are rejected.

Before replacement, archival copies only the requested scope's canonical tar/dry-run/pack paths as raw historical bytes. It does not parse or validate unrelated historical preview data and never grants current acceptance to an archive.

`pipeline-round1.test.mjs` adds focused session regressions using preserved before-source bytes, retained actual tarballs and retained actual Qwik/React/Angular outputs. It performs no package build/install/pack or browser matrix. Like the retained-installation diagnostic, this session test requires the preserved histories; it is not a fresh native acceptance producer. `T14_TEST_OLD=1` selects the original source-inventory regression to demonstrate its actual RED omission. All final production v2 evidence still requires a controller-owned source/output lease.
